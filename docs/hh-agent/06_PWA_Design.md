## 1. デザイン方針 — 信号機型

**この画面が使われる状況は「スマホのロック画面に通知が来て、寝起きや移動中に数秒で判断する」である。** したがって最優先は美しさでも情報量でもなく、**画面を見た瞬間に危険度が分かること**。

- リスクレベルを**画面全体の背景色**で表す。文字を読む前に色で分かる。
- 1 画面 = 1 件。複数件ある場合も「今いちばん危険な 1 件」を全画面で見せ、残りは下部に控えめに積む。
- 判断に必要な最小限（何を・どこで・あと何秒）だけを大きく出す。全文と差分は 1 タップ先。

### 1.1 色だけに意味を持たせない（必須）

信号機型は色に依存するため、**色覚特性や輝度設定で区別できない利用者のために、色以外の手がかりを必ず併記する**。

| リスク | 背景 | アイコン | ラベル文字 |
|---|---|---|---|
| HIGH | 赤 | `⚠` | `HIGH` |
| MEDIUM | 黄 | `！` | `MEDIUM` |
| LOW | 緑 | `✓` | `LOW` |

**アイコンとラベル文字は省略してはならない。** 背景色は補助であって唯一の手がかりではない。

## 2. カラートークン

`style.css` の `:root` に定義し、値をハードコードしない。**ダークモードが既定**（夜間に通知で起こされる用途のため）。ライトは `prefers-color-scheme: light` で上書きする。

```css
:root {
  /* 危険度（ダーク既定） */
  --risk-high-bg:    #4a0f14;
  --risk-high-fg:    #ffd9dc;
  --risk-high-edge:  #e5484d;

  --risk-med-bg:     #402a05;
  --risk-med-fg:     #ffe8bd;
  --risk-med-edge:   #f5a524;

  --risk-low-bg:     #0d2f1d;
  --risk-low-fg:     #c8f2d8;
  --risk-low-edge:   #30a46c;

  /* 中立面（詳細・一覧・ペアリング） */
  --surface:         #101114;
  --surface-raised:  #1a1c21;
  --text:            #ecedee;
  --text-dim:        #9ba1a6;
  --edge:            #2a2d33;

  /* 操作 */
  --deny-bg:         #ecedee;   /* 却下＝安全側。最も押しやすい配色にする */
  --deny-fg:         #101114;
  --approve-edge:    #ecedee;   /* 承認＝危険側。枠線のみで、塗らない */
}
```

**承認ボタンを塗らない**のは意図的な設計である。塗られた大きなボタンは反射的に押される。危険な方向の操作は、押しにくくする。

フォントは**システムフォントスタックのみ**（Web フォント禁止・CSP 違反）。

```css
font-family: -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Yu Gothic UI", sans-serif;
```

## 3. 画面

### 3.1 承認画面（主画面・1 件全画面）

```
┌──────────────────────────┐
│  背景 = リスク色（全面）   │  ← safe-area-inset を尊重
│                          │
│   ⚠   H I G H            │  アイコン + ラベル（色に依存しない）
│   Bash                   │  tool_name
│                          │
│   rm -rf ./dist          │  summary（先頭200字・redaction済）
│   ~/Projects/Reverb      │  workspace / cwd
│                          │
│   R-014 破壊的削除        │  rule_id + reason
│                          │
│   残り  0 4 : 3 1        │  grace_remaining_seconds から算出
│   ██████░░░░░░░░         │  残時間バー
│                          │
│   ┌──────────────────┐   │
│   │    却下する       │   │  56px以上・単タップ・塗り
│   └──────────────────┘   │
│   ┌──────────────────┐   │
│   │  長押しで承認     │   │  56px以上・800ms長押し・枠線のみ
│   └──────────────────┘   │
│                          │
│   全文と差分を見る  ›     │  → 詳細画面
│   ─────────────────      │
│   他に 2 件（MED / MED）  │  ← 2件目以降はここに畳む
└──────────────────────────┘
```

**要素の必須要件**

| 要素 | 規則 |
|---|---|
| 背景 | リスクに応じた `--risk-*-bg`。**点滅・アニメーション禁止**（光過敏性発作の誘発を避ける） |
| アイコン + ラベル | 常時表示。省略不可 |
| `summary` | `textContent` でのみ挿入。**`innerHTML` 禁止**（§9.2） |
| カウントダウン | `grace_deadline` からクライアント側で毎秒再計算。サーバ時刻との差はポーリング時に補正 |
| 残時間バー | `width` を style で設定。残り 60 秒未満で `--risk-high-edge` に変わる |
| 却下ボタン | **単タップ**。押下後は即座に無効化し二重送信を防ぐ |
| 承認ボタン | **800ms 長押し**。押下中は枠が満ちていくプログレスを見せる。離すとキャンセル |
| ボタン高 | 最小 56px。画面下端から 24px 以上空ける（誤タップ防止） |

**却下と承認の縦位置は入れ替えない。** 却下が上（親指が届きやすい）、承認が下。安全側の操作を届きやすい場所に置く。

### 3.2 詳細画面

中立面（`--surface`）に切り替える。リスク色は上端の 4px ボーダーだけに残す。

- コマンド全文（等幅・折り返し・横スクロールさせない）
- 対象パス（realpath 表示）
- `cwd` / `HEAD`
- 差分がある場合は行単位表示。**各行 `document.createElement('div')` + クラス + `textContent`**。`innerHTML` 禁止
- 下端に承認画面と同じ 2 ボタンを固定

### 3.3 一覧画面（2 件以上のとき）

承認画面下部の「他に N 件」をタップで開く。各行は左端 6px のリスク色バー + アイコン + `tool_name` + 残時間。タップで当該件の承認画面へ。

### 3.4 ペアリング画面（初回のみ）

中立面。8 桁コード入力欄（`inputmode="numeric"` / `autocomplete="one-time-code"`）と端末名入力。

エラーは仕様のコードをそのまま日本語表示に対応付ける。**文言を勝手に増やさない。**

| code | 表示 |
|---|---|
| `PAIRING_INVALID` | コードが正しくないか、有効期限（5分）が切れています |
| `PAIRING_CONSUMED` | このコードは既に使用済みです |
| 429 | 試行が多すぎます。`Retry-After` 秒後に再試行してください |

### 3.5 状態画面

| 状態 | 表示 |
|---|---|
| 承認待ちなし | 中立面に「承認待ちはありません」。**緑にしない**（LOW と紛らわしい） |
| Hub 到達不可 | 中立面に「Hub に接続できません。エージェント側は自動的に停止（deny）されます」。**フェイルクローズであることを明示する** |
| `ALREADY_DECIDED` (409) | 「この要求は既に処理されました」 |
| `GRACE_EXPIRED` (422) | 「猶予時間を過ぎたため自動的に却下されました」 |
| `respond` が 500（監査失敗） | 「**承認は成立しています。記録のみ失敗しました**」（§10.4。「失敗」と表示してはならない） |

## 4. 通信

| 項目 | 規則 |
|---|---|
| 初期取得 | `GET /api/approval/pending` |
| リアルタイム | `POST /api/pwa/ws-ticket` → `WS /ws/approval?ticket=` |
| **WS 接続中も 10 秒ポーリングを止めない** | WS の取りこぼしを突き合わせで検出するため（§04 担当表） |
| CSRF | `pending` 応答の `csrf_token` を保持し `respond` に付ける。2 時間で失効するため `pending` のたびに更新 |
| 差分取得 | `GET /api/approval/detail?id=` は詳細画面を開いたときのみ |

---

## 5. Service Worker

- キャッシュ対象は `index.html` / `app.js` / `style.css` / `manifest.webmanifest` **のみ**
- **`/api/*` を絶対にキャッシュしない**
- 承認処理を SW に実装しない
- オフライン時は「オフラインです」の静的表示のみ

---

## 6. 禁止事項（テストで機械的に検査される）

1. `innerHTML` / `insertAdjacentHTML` / `outerHTML` — 例外なし禁止（`test_pwa_no_innerhtml.py`）
2. `eval` / `new Function` / `setTimeout(文字列)`
3. 外部ホストへの参照（CDN・Web フォント・外部画像・外部アイコン）
4. インライン `<script>` / `<style>`（CSP に `'unsafe-inline'` を入れない）
5. `href` / `src` へのユーザー由来値の埋め込み
6. 背景の点滅・明滅アニメーション
